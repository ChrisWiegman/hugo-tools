# hugo-tools

A collection of CLI tools for Hugo bloggers: create drafts, publish them as posts or notes, manage tags and categories, file images, scaffold VS Code tasks, and import your Goodreads library.

> **Never invoke these with `node path/to/script.js`.** Every command is registered as a CLI via the `bin` field in `package.json`, so once installed you run it by name (`hugo-draft`, `hugo-publish`, ...). See [Installation](#installation) for the three ways to do that.

## Requirements

- Node.js 20 or later
- Run every command from the **root of your Hugo site**: the directory containing `hugo.toml` / `hugo.yaml` / `hugo.json` (or `config.*`, or a `config/` directory). Commands exit with an error anywhere else.
- Optional: the VS Code `code` command on your `PATH` (used by `hugo-draft` to open new drafts)

## Installation

Whichever route you pick, you're done as soon as you can run a command by name. You should never need to reference a file under `node_modules/` directly.

**Install locally in your Hugo project (recommended):**

```sh
npm install --save-dev @chriswiegman/hugo-tools
```

Then run commands via `npx`:

```sh
npx hugo-draft
npx hugo-publish content/drafts/my-post.md now
```

...or add them as scripts in your `package.json`:

```json
{
  "scripts": {
    "draft": "hugo-draft",
    "post": "hugo-publish",
    "tags": "hugo-extract-tags"
  }
}
```

so `npm run draft` or `npm run post -- content/drafts/my-post.md now` work too. Don't name a script `publish`: npm runs a script with that name automatically during `npm publish`.

**Install globally and run from any Hugo site root:**

```sh
npm install -g @chriswiegman/hugo-tools
hugo-publish content/drafts/my-post.md now
```

**Run without installing:**

```sh
npx -p @chriswiegman/hugo-tools hugo-draft
npx -p @chriswiegman/hugo-tools hugo-publish content/drafts/my-post.md now
```

This is handy for a one-off run. The VS Code tasks generated by `hugo-vscode` need the package installed locally or globally (see [`hugo-vscode`](#hugo-vscode)).

### Command names

Every command has two names: a `hugo-` prefixed name, used throughout this README, and a short alias kept for backwards compatibility.

| Command | Short alias |
|---|---|
| `hugo-config` | `config` |
| `hugo-vscode` | `vscode` |
| `hugo-draft` | `draft` |
| `hugo-publish` | `publish` |
| `hugo-extract-tags` | `extract-tags` |
| `hugo-add-tags` | `add-tags` |
| `hugo-pick-image` | `pick-image` |
| `hugo-import-books` | `import-books` |

**Prefer the prefixed names, especially with `npx`.** Short names like `publish`, `draft`, `config` and `vscode` also belong to unrelated packages on npm. If hugo-tools isn't installed where you run `npx publish`, npx may offer to download and run that other package instead.

## Configuration

Settings live in `.hugo-tools.json` in your Hugo site root. Run `hugo-config` to generate the file with all defaults, or create it by hand:

```json
{
  "timezone": "America/Chicago",
  "postsDir": "content/posts",
  "draftsDir": "content/drafts",
  "notesDir": "content/notes",
  "booksDir": "content/books",
  "imagesDir": "assets/images",
  "coversDir": "assets/images/books",
  "libraryFile": "content/library.md",
  "vscodeDir": ".vscode"
}
```

All fields are optional; the values shown are the defaults. Paths are relative to the site root.

| Setting | Used by | Purpose |
|---|---|---|
| `timezone` | `hugo-draft`, `hugo-publish`, `hugo-pick-image` | IANA timezone for draft filenames, publish dates, note titles, and image year/month folders |
| `postsDir` | `hugo-publish`, `hugo-extract-tags` | Where published posts go, and where tags/categories are read from |
| `draftsDir` | `hugo-draft`, `hugo-publish` | Where drafts are created; `hugo-publish` only accepts files inside it |
| `notesDir` | `hugo-publish` | Where short posts are published as notes |
| `booksDir` | `hugo-import-books` | Where book files are written |
| `imagesDir` | `hugo-pick-image` | Where images are filed. A leading `assets/` is dropped from the URL path |
| `coversDir` | `hugo-import-books` | Where downloaded cover art is saved (with `--covers`) |
| `libraryFile` | `hugo-import-books` | Page whose `date:` is bumped after an import that writes books. Skipped if the file doesn't exist; set to `""` to turn off |
| `vscodeDir` | `hugo-vscode`, `hugo-extract-tags`, `hugo-add-tags` | Where VS Code config and the tag data files are written |
| `amazonPaApi` | `hugo-import-books` | Optional Amazon Product Advertising API credentials. See [ASIN lookup](#asin-lookup) |

If `.hugo-tools.json` isn't valid JSON, every command prints a warning and falls back to the defaults.

## Commands

### `hugo-config`

Writes a `.hugo-tools.json` with all default values to the current Hugo site root.

```sh
hugo-config
```

Run this once after installing to get a config file you can edit. Exits with an error if `.hugo-tools.json` already exists.

---

### `hugo-vscode`

Scaffolds VS Code configuration for your Hugo site in your `vscodeDir` (default `.vscode/`).

```sh
hugo-vscode
```

Creates these files if they don't already exist. Existing files are left untouched, so delete one to regenerate it:

| File | Purpose |
|---|---|
| `tasks.json` | Tasks: **Create Draft**, **Add Tags**, **Publish Draft (now)**, **Publish Draft (later)**, and **Pick Image** |
| `extensions.json` | Recommends the Markdown word-count and spell-checker extensions |
| `settings.json` | Markdown editor settings (snippet suggestions on, word-based suggestions off) and closing editors for deleted files |

It then runs [`hugo-extract-tags`](#hugo-extract-tags) to generate the tag data and snippets. A site with no posts yet is fine.

Run the tasks from **Terminal → Run Task…**:

- **Create Draft** creates a draft and opens it.
- **Add Tags** runs `hugo-add-tags`.
- **Publish Draft (now / later)** publishes the currently open draft and opens the published file. "Later" prompts for the date.
- **Pick Image** prompts for an image path (drag the file into the terminal to fill it in) and adds it to the currently open file.

The tasks run `npx --no hugo-…`, which uses the package installed in your project (or globally) and fails rather than downloading anything. That's why they don't work with the run-without-installing route.

### `hugo-draft`

Creates a new draft in your `draftsDir` and opens it in VS Code.

```sh
hugo-draft
```

The filename is a timestamp in your configured timezone (`YYYYMMDD-HHMMSS.md`). The draft gets the standard front matter below, and its path is printed. If the `code` command isn't available, the file is still created; it just isn't opened. No `date:` line is written, because `hugo-publish` sets it.

**Generated front matter:**

```yaml
---
title: ""
description: ""
draft: true
images:
  -
categories:
  -
tags:
  -
---
```

---

### `hugo-publish`

Publishes a draft: updates its front matter, moves it into your posts or notes directory, and deletes the draft.

```sh
hugo-publish <draft-path> [now|later] [YYYY-MM-DD]
```

`<draft-path>` must be a `.md` file inside `draftsDir`. It can be relative to the site root (`content/drafts/x.md`), `./`-prefixed, or absolute. If you leave out the mode, you're asked for it; if you choose `later` without a date, you're asked for that too. The date must be a real calendar date in `YYYY-MM-DD` form.

**Examples:**

```sh
# Publish immediately
hugo-publish content/drafts/my-post.md now

# Schedule for 08:00 on a future date
hugo-publish content/drafts/my-post.md later 2026-06-01
```

**Posts or notes:** a draft is published as a **note** when it has fewer than 350 words *and* either no categories or only the `Personal` category. Everything else is a **post**.

**What it does:**

- Sets `date:` to now, or to 08:00 on the scheduled date, in your configured timezone, and removes any `publishDate:`. If the draft already had a different `date:`, it prints a warning (a GitHub Actions warning annotation when running in Actions).
- Sets `draft: false` and writes the title as a properly quoted YAML string. Titles containing quotes are fine.
- **Posts** go to `<postsDir>/YYYY/MM-DD-<slug>.md`. A blank `description: ""` is added if missing, and `categories:`/`tags:` placeholders are kept.
- **Notes** go to `<notesDir>/YYYY/MM-DD-<slug>.md`. `images`, `description`, `tags` and `categories` are removed. A note with no title gets a date title such as `Sunday, 29 March, 2026 - 14:05`.
- The slug comes from the title. The draft is deleted once the published file is written.
- Prints the published path (which the VS Code tasks use to open the new file).

**A post won't publish without** (the draft is left untouched and the error explains why):

- a `title:`
- at least one category. A long draft with no categories is rejected rather than turned into a note.
- at least one tag

It also refuses to overwrite an existing file at the destination path.

### `hugo-extract-tags`

Scans every Markdown file under your `postsDir` and writes two files to your `vscodeDir`:

- `tags-categories.json`: every tag and category, sorted by how many posts use it, with counts
- `markdown.code-snippets`: VS Code snippets so tags and categories autocomplete as you type

```sh
hugo-extract-tags
```

It reads YAML front matter (LF or CRLF line endings) with lists written as blocks (`tags:` followed by `- item` lines), inline (`tags: [a, b]`), or as a single value (`categories: Tech`). Run it periodically to keep the lists fresh. `hugo-vscode` runs it for you on first setup.

Each snippet's trigger is the lowercased name, plus a joined-up form for multi-word names (`Open Source` → `opensource`). A few common names also get short forms (`Technology` → `tech`, `WordPress` → `wp`, `Open Source` → `oss`, ...); that map is in [src/extract-tags.js](src/extract-tags.js). Edits made there inside `node_modules` are lost when you update the package.

---

### `hugo-add-tags`

Interactive picker for categories and tags from your existing taxonomy. It prints a front matter block to paste into a draft.

```sh
hugo-add-tags
```

You pick one category, then as many tags as you like, by number. Enter `0` or press Enter to finish; anything else that isn't a listed number asks again. Requires [`hugo-extract-tags`](#hugo-extract-tags) to have been run at least once.

### `hugo-pick-image`

Moves an image into your `imagesDir` under the current year and month, then adds it to a content file or copies its URL path to the clipboard.

```sh
hugo-pick-image <image-file> [content-file]
```

**What it does:**

- Moves `<image-file>` to `<imagesDir>/YYYY/MM/<filename>`, using the year and month in your configured timezone. The directory is created if needed, and moving from another drive works. It refuses to overwrite an existing file there, and an image already in place isn't moved.
- Builds the Hugo URL path by dropping a leading `assets/` (e.g. `assets/images` → `/images/YYYY/MM/<filename>`).
- With a `[content-file]`:
  - If the front matter has an `images:` field, the path is added to it. The `  -` placeholder is replaced, inline (`images: []`) and single-value forms become a block list, and the existing indentation and line endings are kept.
  - Otherwise a `![](path)` Markdown image is added to the end of the body.
- Without a `[content-file]`, it copies the URL path to the clipboard. If no clipboard tool is available, the path is printed instead.

Supported formats: `.jpg`, `.jpeg`, `.png`, `.webp`, `.gif`.

**Examples:**

```sh
# Move photo.jpg and add it to a draft
hugo-pick-image ~/Downloads/photo.jpg content/drafts/my-post.md

# Move photo.jpg and copy its path to the clipboard
hugo-pick-image ~/Downloads/photo.jpg
```

Clipboard support: macOS (`pbcopy`), Windows (`clip`), Linux (`xclip`, `xsel`, or `wl-copy`, whichever is available).

### `hugo-import-books`

Imports the "read" shelf of a [Goodreads CSV export](https://www.goodreads.com/review/import) into Hugo content files under your `booksDir`.

```sh
hugo-import-books path/to/goodreads_library_export.csv [--covers] [--refresh-asins]
```

| Flag | Effect |
|---|---|
| `--covers` | Download cover art (off by default). See [Cover art](#cover-art) |
| `--refresh-asins` | Retry ASIN lookups for books that previously had none. See [ASIN lookup](#asin-lookup) |

**To export from Goodreads:** Account → My Books → Import and Export → Export Library.

**What it writes:** one file per book at `<booksDir>/<author-last-first>/<title-slug>.md` (e.g. `content/books/king-stephen/the-gunslinger.md`), with the folder taken from Goodreads' "Author l-f" column:

```yaml
---
title: "The Gunslinger"
author: "Stephen King"
rating: 4
finished:
  - "2024-05-01"
links:
  amazon: "https://www.amazon.com/s?k=9780452284692"
  openlibrary: "https://openlibrary.org/search?isbn=9780452284692"
  goodreads: "https://www.goodreads.com/book/show/43615"
reference:
  isbn: "9780452284692"
  asin: ""
cover: ""
---

Your Goodreads review, if any.
```

- Only books on the **read** shelf are imported. `finished` uses "Date Read", or "Date Added" when that's blank.
- `rating` is your Goodreads star rating (0 means unrated).
- Your review becomes the body. Goodreads' HTML line breaks and bold/italic tags are converted to Markdown, so paragraphs survive Hugo's default HTML stripping.
- The Amazon link searches by ISBN-13, then ISBN-10, then title and author.
- Only books with an ISBN get the ISBN, ASIN and cover lookups.

**Re-running is safe.** Existing files are matched by Goodreads book ID, then ISBN, then path, so you never get duplicates. For a matched file:

- New finish dates are merged into `finished`. Dates are only ever added, never replaced or removed.
- `rating` is updated when Goodreads has a different rating above 0. An unrated Goodreads book never overwrites a rating you entered in the file.
- `reference.isbn`, `reference.asin` and `cover` are only filled in when blank. Values already in the file (e.g. entered by hand) are never overwritten.
- If the book's title changed on Goodreads, the file is moved to the new slug and its `title` is updated. If another file already exists at the new path, the book is updated in place instead and a warning is printed.
- Only front matter is ever edited. Your review and other body text are left alone.
- Files with nothing to change are skipped.

After an import that writes anything, the `date:` of your `libraryFile` (default `content/library.md`) is bumped. The run ends with a summary of books created, updated, renamed and skipped.

**Re-reads:** Goodreads' CSV export only ever contains the *most recent* "Date Read" for a book, even when its "Read Count" shows it was finished more than once. So if you re-read a book, the next export carries the new date, and it's added to `finished` automatically. What the export can't give you is *earlier* read dates for a book you'd already read more than once before you started tracking it here. When "Read Count" is higher than the number of dates on file, the import prints a line like:

```
NOTE: king-stephen/the-gunslinger.md shows 3x read on Goodreads but only 1 date(s) on file — Goodreads only exports the latest read date, so add earlier ones to 'finished' by hand.
```

This is informational only: the file isn't touched, and nothing else about the import is blocked. Add the missing dates to the file's `finished:` list yourself; the note stops appearing once the counts match. The summary also reports how many books were flagged (`Rereads needing dates`).

#### ASIN lookup

Goodreads exports don't include an ASIN, so one is looked up per ISBN from Open Library, then Google Books. If neither has one, it's left blank (`""`). Each ISBN is only looked up once. On later runs, files whose `reference` block already has a blank ASIN are skipped unless their ISBN changed. Pass `--refresh-asins` to retry them. Requests time out after 15 seconds, and a failed request just moves on to the next source.

To use the Amazon Product Advertising API (PA-API 5) as a final fallback, add credentials to `.hugo-tools.json`:

```json
{
  "amazonPaApi": {
    "accessKey": "",
    "secretKey": "",
    "partnerTag": ""
  }
}
```

`host` (default `webservices.amazon.com`), `region` (default `us-east-1`) and `marketplace` (default `www.amazon.com`) can be added for other Amazon stores. This requires an approved Amazon Associates account with Product Advertising API access. Don't commit real credentials to a public repository.

#### Cover art

Off by default; pass `--covers` to fetch it. Each book's ISBN is looked up with Open Library's cover API, then Google Books, and left blank if neither has one. Images are saved to `<coversDir>/<author-last-first>/<title-slug>.<ext>` (default `assets/images/books/...`). The `cover` field is set to the matching Hugo URL path (e.g. `/images/books/king-stephen/it.jpg`). On existing files only a blank `cover` is filled in, and no cover requests are made unless `--covers` is passed.

## Development

```sh
npm ci          # install dependencies
npm test        # run the test suite (node:test)
npm run lint    # run ESLint
make change     # add a changelog entry with changie
```

Every change should come with a changelog entry in `.changes/unreleased/`. `make changelog` batches them into a release.
